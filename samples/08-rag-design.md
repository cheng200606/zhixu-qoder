# RAG 设计笔记：引用、预算与可回查

一个可靠的 RAG 系统，难点不在把文本塞进模型，而在「让模型知道自己拿到的是什么」。我的设计原则是三条：每条上下文都要能回查到原文；上下文要受字节预算约束；检索结果要区分关键词命中和语义命中。

切块策略：笔记按二级标题切，文档按段落切，PDF 按页切。块太小会丢上下文，太大又会挤占预算。经验值是每块 300 到 800 字，保留标题作为块的第一行，方便引用时显示来源。

检索策略：先用全文检索保证术语命中，再考虑向量召回补充语义相近的表达。两路结果要合并去重，不能简单拼接。没有配置 embedding 时，全文检索仍然能覆盖大部分内部资料查询。

上下文组装：不要把所有命中都塞进去。按 query 选出最相关的几条，按预算裁剪，输出时附带 citation。模型回答里应该引用 entry_id，应用层据此回查原文，避免模型编造。

评估指标：证据召回率、整页 F1、Recall@k、MRR。内部知识库还要看「用户是否愿意把这段上下文粘贴给 AI」，这是最直接的使用效果指标。

工程注意：记忆条目要支持修订和停用，历史版本保留；删除是软删除，检索时默认过滤；重启后同一 scope 的数据必须还在。

这套设计正是知序采用的结构：PowerContext 负责记忆、检索、引用和预算组装，应用只负责导入、展示和交互。
